## MODIFIED Requirements

### Requirement: 守护进程健康检查

系统 SHALL 将健康检查收敛为按请求触发的最小活性判断，而不是依赖后台心跳或长期探活协议。

#### Scenario: 请求前检查共享守护进程
- **WHEN** 数据库工具准备复用共享 Java 桥接
- **THEN** 系统应先检查该进程是否仍然存活
- **AND** 若进程存活，则直接复用当前共享运行时

#### Scenario: 请求前发现进程已退出
- **WHEN** 数据库工具在执行前发现共享 Java 桥接已退出
- **THEN** 系统应销毁旧的共享运行时引用
- **AND** 重新创建新的共享 Java 桥接
- **AND** 在新桥接就绪后再执行本次请求

### Requirement: 自动重启不健康的进程

系统 SHALL 仅在请求边界做最小重建，不再引入后台自动恢复、心跳驱动重启或当前请求重放。

#### Scenario: 边界内重建共享桥接
- **WHEN** 共享桥接在请求开始前被判定为不可用
- **THEN** 系统应在本次请求执行前完成一次重建
- **AND** 不得保留旧桥接的状态

#### Scenario: 请求执行中出现超时或异常退出
- **WHEN** Java 桥接在当前请求执行过程中超时或异常退出
- **THEN** 当前请求应直接失败
- **AND** 系统应将共享运行时标记为待重建
- **AND** 下一次请求可重新创建新的共享桥接

## REMOVED Requirements

### Requirement: Java 端心跳发送
**Reason**: 心跳协议会扩大协议面和后台状态，但当前阶段只需要按请求触发的最小活性判断。
**Migration**: 删除心跳消息；健康判断改为请求开始前检查进程是否存活。

### Requirement: 防止连续重启
**Reason**: 连续重启限制服务于后台自动重启模型，不属于请求边界重建的必要复杂度。
**Migration**: 无；共享运行时仅在请求入口被显式重建。

### Requirement: 健康状态查询接口
**Reason**: 当前系统不再暴露长期守护进程观测接口。
**Migration**: 无；如未来确需状态观测，再单独设计。
