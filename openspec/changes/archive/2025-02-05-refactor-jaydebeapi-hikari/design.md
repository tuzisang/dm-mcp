# 设计文档：Java 守护进程 + HikariCP 重构

## Context

### 当前状态

项目使用 `dmpython`（达梦官方 Python 驱动）连接达梦数据库，但该驱动不支持 macOS ARM64 平台，导致 Apple Silicon Mac 用户无法正常开发。

### 约束条件

- **MCP 工具接口必须保持兼容**：上层调用者不能感知到底层实现的变化
- **性能要求**：连接池必须支持并发查询，不能成为性能瓶颈
- **异常处理**：Java subprocess 调用需要完善的异常捕获和错误传播
- **依赖管理**：JAR 文件需要从本地 Maven 仓库复制到项目中

### 技术栈

- **Python**: >=3.12
- **Java**: JRE 8+（SDKMAN 管理）
- **JDBC 驱动**: dm-jdbc-1.8.jar
- **连接池**: HikariCP 5.1.0

## Goals / Non-Goals

**Goals:**

1. 跨平台兼容：支持 macOS ARM64、Linux、Windows
2. 高性能连接：使用 HikariCP 提供连接池能力
3. 接口兼容：现有 MCP 工具接口和行为完全不变
4. 易于维护：代码结构清晰，依赖管理规范

**Non-Goals:**

1. 不修改 MCP 工具的接口定义
2. 不改变配置文件格式（dm_config.json）
3. 不实现新的数据库功能（只替换底层实现）

## Decisions

### 决策 1：使用 Java 守护进程（通过 stdin/stdout JSON 通信）

**选择：** Java 作为长期守护进程运行，通过 stdin/stdout 与 Python 通信

**理由：**
- JPype 1.6.0 在 macOS ARM64 + Python 3.12 上有兼容性问题（`Can't find org.jpype.jar support library`）
- jaydebeapi 依赖 JPype，存在相同问题
- 守护进程模式避免了重复启动 Java 进程的开销
- 直接使用 Java 原生代码，无需 Python JDBC 桥接层
- 已验证可行（测试用例成功连接到数据库，发现 504 张表）

**替代方案：**
- JPype/jaydebeapi：在当前平台有 bug，无法使用
- 每次查询启动新 Java 进程：性能开销太大

**权衡：**
- ✅ 跨平台兼容性好
- ✅ 隔离性好，Java 崩溃不影响 Python 进程
- ✅ 无进程启动开销（进程长期存活）
- ✅ 连接池在 Java 进程内持久化
- ❌ 需要管理进程生命周期
- ❌ JSON 序列化开销（但较小）

### 决策 2：使用 HikariCP 作为连接池

**选择：** HikariCP 4.0.3（Java 8 兼容版本）

**理由：**
- 业界性能最好的 JDBC 连接池（benchmark 验证）
- 轻量级、配置简单
- 与 Spring Boot、Hibernate 等框架广泛集成
- 4.0.3 版本兼容 Java 8，适合达梦数据库环境

**替代方案：**
- DBCP2：性能较差
- C3P0：维护停滞

### 决策 3：JAR 文件管理方式

**选择：** 从本地 Maven 仓库复制到项目 `lib/` 目录

**理由：**
- 离线可用（不需要每次从网络下载）
- 版本固定（通过文件名控制）
- 简单直接（不需要额外的依赖管理工具）

**替代方案：**
- 运行时从 Maven 中央仓库下载：需要网络，可能不稳定
- 使用 pyinstaller 打包：增加复杂度

### 决策 4：Java 守护进程设计

**选择：** 单一 Java 类 `DmJdbcBridge`，作为守护进程运行，通过标准输入/输出通信

**理由：**
- 简单：不需要 RPC 框架
- 高效：JSON 序列化开销小
- 可测试：容易单元测试
- 持久化：进程和连接池长期存活

**通信协议：**
```
Python → Java: JSON 格式的 SQL 请求（通过 stdin）
Java → Python: JSON 格式的查询结果（通过 stdout）
```

**进程管理：**
- Python 启动时创建 Java 守护进程
- Python 退出时终止 Java 进程
- 支持进程健康检查和自动重启

## 架构设计

### 整体架构

```
┌─────────────────────────────────────────────────────────────┐
│                         main.py                              │
│                    (MCP Server)                              │
│  ┌─────────────────────────────────────────────────────┐    │
│  │  启动时创建 Java 守护进程                            │    │
│  └─────────────────────────────────────────────────────┘    │
└───────────────────────────┬─────────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────────┐
│                    db/client.py                              │
│  ┌─────────────────────────────────────────────────────┐    │
│  │         DmClient (Python 接口层)                     │    │
│  └───────────────────────────┬─────────────────────────┘    │
└──────────────────────────────┼──────────────────────────────┘
                               │ stdin/stdout (JSON)
┌──────────────────────────────▼──────────────────────────────┐
│              DmJdbcBridge.java (守护进程)                   │
│  ┌─────────────────────────────────────────────────────┐    │
│  │           HikariDataSource (连接池, 长期存活)        │    │
│  │              - 最小连接数: 2                         │    │
│  │              - 最大连接数: 10                        │    │
│  └───────────────────────────┬─────────────────────────┘    │
│  ┌───────────────────────────▼─────────────────────────┐    │
│  │        dm.jdbc.driver.DmDriver (JDBC 驱动)          │    │
│  └───────────────────────────┬─────────────────────────┘    │
└──────────────────────────────┼──────────────────────────────┘
                               │
                         达梦数据库
```

**关键特性：**
- **守护进程**: Java 进程在 MCP 服务器启动时创建，退出时销毁
- **持久连接池**: HikariCP 连接池在 Java 进程内长期存活
- **零启动开销**: 查询无需启动新进程，直接通过 stdin/stdout 通信

## Risks / Trade-offs

### 风险 1：序列化性能

**风险：** 大结果集的 JSON 序列化/反序列化开销

**缓解措施：**
- AI 调用 MCP 时会自动添加分页（LIMIT/OFFSET）避免大结果集
- JSON 序列化开销对于中小结果集（<1000 行）可忽略

### 风险 2：守护进程管理

**风险：** Java 守护进程可能崩溃或卡死

**缓解措施：**
- 实现健康检查机制（定期发送 ping 消息）
- 支持自动重启守护进程
- 设置合理的超时时间，防止无限等待

### 风险 3：异常处理复杂性

**风险：** Java 和 Python 异常体系不同，错误传播可能丢失信息

**缓解措施：**
- 统一错误码映射（Java 异常 → Python 自定义异常）
- 完整的堆栈信息传递
- 详细的日志记录

### 风险 4：JAR 文件版本管理

**风险：** 手动管理 JAR 文件可能导致版本不一致

**缓解措施：**
- 在 `pyproject.toml` 中记录 JAR 版本
- 提供脚本自动从 Maven 仓库下载
- 文档中说明 JAR 文件来源和版本

## Migration Plan

### Phase 1: 准备阶段

1. 复制 JAR 文件到 `lib/` 目录
2. 创建 `DmJdbcBridge.java` 基础框架
3. 编写单元测试验证 Java 桥接服务

### Phase 2: 核心实现

1. 实现 `JavaBridgeClient` 类（管理 Java 守护进程）
2. 编译 `DmJdbcBridge.java`（Java 桥接服务）
3. 实现 `DmClient` 类（基于 JavaBridgeClient）
4. 实现 HikariCP 连接池配置（在 Java 端）
5. 迁移现有 7 个 MCP 工具到新实现

### Phase 3: 测试验证

1. 运行现有测试用例
2. 手动测试每个 MCP 工具
3. 性能测试（对比 dmpython 实现）
4. 边界条件测试（网络异常、超时等）

### Phase 4: 上线部署

1. 更新文档（README.md、CLAUDE.md）
2. 发布新版本
3. 监控运行状态

### 回滚策略

如果出现问题，可以：
1. 保留 `db/client.py` 的 dmpython 实现（分支或备份）
2. 通过配置切换实现（环境变量 `DM_USE_JDBC=true/false`）
3. Git 回退到上一个稳定版本

## Open Questions

1. **Q:** 是否需要支持连接池的动态配置（运行时调整）？
   - **A:** 当前不支持，需要在配置文件中定义。如果需要，可以在后续版本添加。

2. **Q:** 守护进程崩溃后如何恢复未完成的查询？
   - **A:** 当前方案是直接返回错误给上层。如果需要支持重试，可以在 Python 层实现。

3. **Q:** 是否需要支持 SSL/TLS 连接？
   - **A:** 当前版本不支持。达梦 JDBC 驱动支持 SSL，可以在后续版本添加配置项。

4. **Q:** 多个 MCP 服务器实例是否可以共享同一个 Java 守护进程？
   - **A:** 当前不支持，每个实例有独立的守护进程。可以后续考虑进程池模式。

5. **Q:** 大结果集如何处理？
   - **A:** 当前方案是一次性返回 JSON。AI 调用 MCP 时会自动添加分页（LIMIT/OFFSET）来避免大结果集，无需特殊处理。
