## Why

当前项目已经演化出多套重复校验、重复桥接资产、跨层状态恢复和大量附属协议。考虑到该 MCP 会在短时间内被频繁调用，Java 守护进程、连接池以及短 TTL 查询缓存本身仍然是必要能力，但围绕它们扩散出的重复校验、动态调优、心跳遥测和脚本资产并没有形成当前阶段真正需要的最小闭环。

现在需要把系统收敛回当前真正需要的最小闭环：在 MCP 进程内复用一个最小共享运行时，对只读查询提供约 1 分钟的显式缓存，稳定执行只读查询/诊断查询，返回统一结果，并保留必要的 Java JDBC 连接池与守护进程能力。

## What Changes

- 保留只读查询缓存，但把缓存策略收敛为显式的短 TTL 行为，而不是散落的隐式状态。
- 删除重复的 SQL/标识符校验实现，收敛为单一验证入口。
- 删除未被运行路径使用的重复 Java 桥接源码和重复配置资产。
- 将 Python 客户端与 Java 桥接收敛为 MCP 进程内共享的最小运行时，避免每次工具调用都销毁守护进程和连接池。
- 保留守护进程与连接池复用，但移除心跳遥测、池状态查询、动态连接池调优、重启计数等外围扩展点。
- 收敛配置面，只保留当前闭环真正需要的数据库连接参数与查询超时。
- 删除依赖真实本地数据库/JDK 布局的脚本式测试，保留可重复执行的单元回归测试。

## Capabilities

### New Capabilities

无

### Modified Capabilities

- `database-client`: 收敛客户端职责为进程内共享的薄执行器，复用守护进程与连接池，移除重复校验和多处构造路径。
- `java-bridge`: 收敛桥接协议为最小请求/响应闭环，删除心跳、自动恢复、连接池状态查询等守护进程扩展点。
- `connection-pool`: 保留 HikariCP 作为短时高频调用下的共享内部实现，但删除当前阶段不需要的池状态暴露、运行时调优和监控承诺。
- `connection-pool-config`: 删除运行时连接池调优能力，收敛配置为最小必要集。
- `health-check`: 将健康检查收敛为按请求触发的最小活性判断，删除心跳和长期守护探活协议。
- `retry-policy`: 删除可配置重试策略和相关状态追踪能力。
