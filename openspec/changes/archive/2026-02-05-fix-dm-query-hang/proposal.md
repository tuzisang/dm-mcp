## Why

`dm_query` 工具在某些情况下会假死（永久阻塞），导致用户体验严重受损。根本原因是 `db/java_bridge.py` 中的 `_read_response()` 方法使用阻塞式 `stdout.readline()` 调用，在 Java 守护进程存活但无响应时无法超时恢复。此外，重试机制的累积延迟（最长可达 6 分钟）和缺乏心跳检测机制进一步加剧了问题。

## What Changes

### 高优先级修复

- **非阻塞 I/O 机制**: 将阻塞式 `readline()` 替换为基于 `threading.Timer` 的超时包装器，确保所有 I/O 操作都能在指定超时后返回
- **心跳检测**: 实现 Java 桥接进程的健康检查机制，快速发现进程假死状态
- **改进错误恢复**: 在检测到超时或进程假死时，自动重启 Java 守护进程并重试查询
- **🔴 连接资源管理**: 确保在假死、超时、主动断开等异常场景下，数据库连接被正确关闭，避免连接池耗尽

### 中优先级优化

- **重试机制优化**: 减少重试次数（3→1）和延迟时间（5秒→1秒），缩短总体响应时间
- **连接池配置调整**: 增加 HikariCP 连接池最大连接数（10→20）和连接超时（30秒→60秒），降低连接获取失败概率
- **详细调试日志**: 添加关键路径的调试日志，便于诊断假死问题

### 低优先级改进

- **监控指标**: 添加查询耗时、超时次数等监控指标导出
- **缓存优化**: 确保缓存操作不会阻塞数据库查询执行

## Capabilities

### New Capabilities

- `non-blocking-io`: 非阻塞 I/O 和超时控制机制，确保所有桥接通信都有明确的超时保障
- `health-check`: Java 桥接进程健康检查能力，包括心跳检测、进程状态监控和自动恢复
- `retry-policy`: 可配置的重试策略，支持自定义重试次数、延迟和退避算法
- `connection-pool-config`: 动态连接池配置管理，支持运行时调整连接池参数
- `connection-cleanup`: 🔴 连接资源清理机制，确保异常场景下数据库连接被正确释放

### Modified Capabilities

- `java-bridge`: 增强错误处理和恢复能力，添加超时控制和状态监控接口

## Impact

### 受影响的代码模块

- `db/java_bridge.py`: 核心修复，重构 `_read_response()` 和 `execute_query()` 方法
- `db/DmJdbcBridge.java`: 添加心跳响应逻辑和改进的错误输出
- `db/client.py`: 优化重试机制和配置处理
- `db/config.py`: 添加新的配置项（超时控制、心跳间隔、重试策略）
- `core/cache.py`: 确保缓存操作不会阻塞（可选优化）

### API 变更

- **新增配置参数** (向后兼容):
  - `io_timeout`: I/O 操作超时时间（秒），默认 30
  - `health_check_interval`: 心跳检测间隔（秒），默认 15
  - `max_retries`: 最大重试次数，默认 1
  - `retry_delay`: 重试延迟（秒），默认 1
  - `pool_max_connections`: 连接池最大连接数，默认 20
  - `pool_connection_timeout`: 连接获取超时（毫秒），默认 60000

### 依赖和系统

- 无新增外部依赖
- Python 标准库: `threading`, `queue`（已使用）
- Java: HikariCP 配置参数调整
- 向后兼容现有配置文件

### 性能影响

- **正面**: 减少假死延迟（从最长 6 分钟降至 30-60 秒）
- **正面**: 提高系统稳定性，自动恢复故障状态
- **可忽略**: 心跳检测 CPU 开销 < 1%
- **可忽略**: 连接池资源增加（约 10MB 内存）
